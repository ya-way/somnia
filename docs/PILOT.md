# Somnia — partner and investor brief

**An AI that learns how you live.**

Somnia proposes a software service layer for compatible smart sleep hardware: combine nightly signals, lifestyle context and a correctable personal memory to make the experience useful beyond a morning chart.

## The problem to validate

Device measurements can reveal patterns without explaining the person's circumstances. The commercial hypothesis is that people and manufacturers will value an ongoing, contextual experience enough to return to it and pay for it. That hypothesis needs a partner pilot; this repository does not claim it has already been validated.

## The product direction

An integrable, manufacturer-branded sleep assistant. It would ask about the day behind the night, keep a user-controlled memory, explain longitudinal patterns and support small, reviewable wellbeing actions. The intended entry point is the smart mattress; broader smart-home personalization is a longer-term possibility.

The open prototype demonstrates the interaction and data contract today. It runs with synthetic data and deterministic rules. Actual device integrations, model-backed reasoning, health outcomes and commercial retention are not yet demonstrated.

| One device API or export format    | A documented and tested adapter                     |
| A real household or retail setting | A focused, branded prototype experience             |
| Consenting pilot participants      | Context, memory correction and weekly review flows  |
| A pilot sponsor and feedback owner | Instrumentation and a transparent evaluation report |

## A proposed 4–6 week pilot

**Weeks 1–2: connect.** Establish intended use, device availability, consent, access permissions, data minimization and the evaluation plan. Connect one source. Agree on explicit stop conditions.

**Weeks 3–4: experience.** Test contextual explanations and memory correction with an appropriately scoped pilot cohort. Record feedback and failure cases. Distinguish device observations from user reports and system hypotheses.

**Weeks 5–6: decide.** Review engagement, usefulness, correction frequency, operational cost and willingness to pay. Decide whether to iterate, expand or stop. Do not present subjective feedback as a clinical efficacy result.

The schedule is a proposal, subject to partner data access and the scope of the AI integration. Recruitment and any model processing require a separate, concrete agreement.

## What to measure

- **Repeat use:** participants returning for another check-in, with the denominator and time window stated.
- **Explanation usefulness:** structured participant ratings plus examples of unhelpful explanations.
- **Memory quality:** corrections, stale records and whether subsequent explanations respect those corrections.
- **Boundaries:** unsupported causal or medical claims and whether the experience handles them appropriately.
- **Commercial interest:** a partner's willingness to fund integration and users' stated willingness to pay, kept distinct from actual revenue.
- **Unit economics:** observed infrastructure and support costs per active pilot participant.

Set numeric thresholds with the partner before launch. No target is presented as an achieved result.

## Business model hypotheses

Begin with a paid integration pilot. If the experience proves useful, evaluate software licensing, a per-device service fee or optional user subscription with a manufacturer. The open reference implementation supports inspection and adoption; integration reliability, evaluation quality and partner operations would need to earn the commercial value.

Pricing, customer acquisition cost, retention, gross margin and defensibility are open questions. There are no claimed partnerships, customers, revenue, trial outcomes or regulatory approvals in this release.

## What initial funding would buy

Fund a defined learning milestone: one real adapter, one bounded context-and-memory experience, an evaluation harness and a documented pilot decision. A sensible next discussion is about resources, access and a pilot budget. Equity, valuation and fundraising amount are intentionally unspecified.
